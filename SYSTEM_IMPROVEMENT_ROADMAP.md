# Logo Playground improvement roadmap

This document keeps larger improvements out of the rendering-repair change set.
Correctness comes before adding more commands or visual effects.

## Command contract after the repair

| Command | Current contract | Status |
| --- | --- | --- |
| `fd n` | Move forward `n` pixels and draw when the pen is down. | Verified |
| `bk n` | Move backward without changing heading. | Verified |
| `tl n` | Turn counter-clockwise by `n` degrees. | Fixed and verified |
| `tr n` | Turn clockwise by `n` degrees. | Fixed and verified |
| `repeat n [...]` | Run the block exactly `n` times; nesting is supported. | Fixed and verified |
| `penup` / `pendown` | Disable or enable drawing without leaking state between replays. | Fixed and verified |
| `hideturtle` / `showturtle` | Hide or show only the marker. | Fixed and verified |
| `setsc hex` | Set line color from a six-digit hex value, with or without `#`. | Fixed and verified |
| `setbc hex` | Fill the exported canvas background with a six-digit hex value. | Fixed and verified |
| `setsw n` | Set stroke width; values below `0.25` are clamped. | Verified |
| `setpos x y` | Teleport to absolute canvas coordinates without drawing. | Verified app convention |
| `home` | Teleport to `(400, 400)`, face right, and retain pen/style state. | Verified app convention |
| `save` / `load` | Removed from the accepted UI language because the old methods did not save or load anything. | Deferred |

The parser now accepts normal whitespace, uppercase commands, decimal values,
negative coordinates, nested repeats, and both forms of hex colors.

## Next: lock correctness with automated tests

1. Add unit tests for every parser command and invalid-input boundary.
2. Add canvas pixel tests for heading, pen state, colors, repeat counts, and
   replay determinism.
3. Add a complexity budget so extremely large nested repeats cannot freeze the
   browser.
4. Add visual regression snapshots for several canonical designs.

## Next: align and regenerate the example gallery

Some legacy JPG previews may have been generated when `repeat n` executed
`n + 1` times and left/right turns used the canvas directions incorrectly.
Do not change the engine back to match those bugs.

1. Select a small canonical example set.
2. Render each preview through the repaired engine.
3. Replace stale JPG previews with generated PNG or SVG assets.
4. Add a script that regenerates previews from the command data so they cannot
   drift again.
5. Review expensive or near-duplicate examples before keeping all of them.

## Later: real projects and history

1. Add undo and redo for command add, edit, delete, clear, and example load.
2. Export and import the command program as versioned JSON.
3. Add browser autosave with explicit recovery messaging.
4. Reintroduce project `save` and `load` only after they perform real,
   test-covered persistence.
5. Keep PNG export as a separate output action.

## Later: creative “wow” features

1. Animated turtle playback with pause, speed, and step controls.
2. Layered presets for palettes, stroke styles, symmetry, and canvas sizes.
3. SVG export for resolution-independent artwork.
4. Shareable URLs with compact, validated command programs.
5. A searchable gallery with favorites and complexity indicators.
6. Optional center-origin coordinates and standard Logo `home` movement after a
   documented compatibility decision.

## Quality gates

- No command may mutate state outside a deterministic replay.
- No asynchronous image load may leave a canvas transform active.
- Example previews must be generated by the same engine used in the editor.
- Fake or placeholder commands must not appear in command help.
- Desktop and mobile layouts must have no horizontal overflow.
- Lint, TypeScript, production build, command behavior checks, and visual checks
  must pass before release.
